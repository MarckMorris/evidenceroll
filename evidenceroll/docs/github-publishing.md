# GitHub Publishing Guide

## Repository settings

- **Name:** `evidenceroll`
- **Description:** Evidence-aware progressive delivery for ML models when ground truth arrives late.
- **Visibility:** public
- **Topics:** `mlops`, `ml-platform`, `progressive-delivery`, `model-monitoring`, `canary`,
  `kserve`, `argo-rollouts`, `fastapi`, `prometheus`, `kubernetes`
- **Default branch:** `main`

Create an empty GitHub repository without an autogenerated README, license, or `.gitignore`; all
three already exist here.

## First push

Run these commands from the extracted `evidenceroll` directory:

```bash
git init
git add .
git commit -m "feat: ship EvidenceRoll evidence-aware delivery control plane"
git branch -M main
git remote add origin https://github.com/MarckMorris/evidenceroll.git
git push -u origin main
```

## Protection and presentation

1. Require the `test` and `container` workflows before merging to `main`.
2. Enable Dependabot alerts and private vulnerability reporting.
3. Disable force pushes and branch deletion on `main`.
4. Create a `v0.1.0` release only after the first green CI run.
5. Pin this repository beside `pyrrho` on the profile; together they show change-risk reasoning at
   the infrastructure and ML-release layers.
6. Add one dashboard screenshot only after running the repository yourself. Do not use an image that
   implies production traffic or external adoption.

No repository secret is required for the acceptance suite. Runtime model credentials, API keys, and
audit HMAC material belong in the deployment platform, never in GitHub.
